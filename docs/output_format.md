# Форматы выходных файлов

Здесь описаны все файлы, которые пишет генератор, и соглашения, на которых они построены.
`EXP` — папка эксперимента, `<вид>` — номер камеры 0–3. Идентификатор вида —
`<дом>/<комната>/<вид>`.

## Системы координат

| Система | Единицы | Оси | Где встречается |
|---|---|---|---|
| исходный 3D-FRONT | метры | Y вверх | описания сцен `3D-FRONT/<дом>.json` |
| glTF переработки MIDI-3D | нормированы **отдельно для каждой комнаты** | Y вверх | `*.glb` |
| мир комнаты | нормированные | Z вверх | `render.json`: камеры, контур, границы; глубина в HDF5 |
| мир в метрах | метры | Z вверх | `metadata.layout_geometry_world`, `metadata.camera_location_world` |
| **система камеры** | метры | Z вверх, начало в камере, оси мира | эталон: `layout`, `objects[].bbox` |
| единичная рамка предмета | безразмерные | оси рамки | `objects/*/mesh.ply` |

Переход из glTF в мир комнаты: `(x, y, z) → (x, −z, y)`. В метры:
`метры = единицы × metric_scale` комнаты, см. [metric_scale.md](metric_scale.md).

**Эквиректангулярная проекция.** Панорама W×H = 1024×512, долгота растёт линейно по x,
широта — по y. Для точки `d = P − камера`:

```
долгота  λ = atan2(d.x, d.y)                   # 0 — направление +Y
x        = ((0.5 + λ/(2π)) mod 1) · W − 0.5
широта   φ = atan2(d.z, hypot(d.x, d.y))
y        = (0.5 − φ/π) · H − 0.5               # верх изображения — зенит
```

Центр изображения смотрит вдоль +Y. Шов (x = 0 и x = W) приходится на направление −Y,
за спиной камеры. Сдвиг кадра на W/2 переносит шов вперёд.

**Рамка предмета.**

```json
{"center": [cx, cy, cz], "size": [sx, sy, sz], "basis": [[ax, ay, 0], [bx, by, 0], [0, 0, 1]]}
```

Строки `basis` — оси рамки в координатах мира: первая — главная ось следа предмета на
полу (метод главных компонент по точкам XY), вторая — перпендикуляр к ней, третья —
вертикаль. Рамка всегда стоит вертикально, крена и тангажа нет. Угол рамки:
`center + Σ_k (±size_k / 2) · basis[k]`.

> **У рамки нет «переда».** Ось строится по форме следа, а не по передней стороне
> предмета, поэтому рамки одного предмета, повёрнутые на 180°, равнозначны. При
> сравнении ориентаций это нужно учитывать.

## Рендер: `outputs/<часть>/<дом>/<комната>/`

### `{0..3}.hdf5` — одна панорама на файл

| Ключ | Форма | Тип | Что |
|---|---|---|---|
| `colors` | 512×1024×3 | uint8 | цвет |
| `depth` | 512×1024 | float32 | расстояние вдоль луча до поверхности, **в нормированных единицах**, без сглаживания |
| `normals` | 512×1024×3 | float32 | нормали поверхности в мире комнаты |
| `instance_segmaps` | 512×1024 | целое | номер экземпляра в каждом пикселе |
| `instance_attribute_maps` | скаляр | строка JSON | `[{"idx", "name", "source_label", "source_file"}, ...]` |

Пиксель связывается с предметом через `source_file` — имя файла GLB, а через то же имя —
с эталоном (`objects[].attributes.source_glb`). Номер экземпляра меняется от рендера
к рендеру, хранить его как идентификатор нельзя. Предмет, полностью закрытый другими,
записи в `instance_attribute_maps` не получает.

Глубина валидна там, где `isfinite(depth) & (depth > 0) & (depth < 1e6)`: в направлениях
без поверхности (окна, проёмы) значения нет. В метры глубина переводится умножением на
`metric_scale` комнаты.

```python
import h5py, json
with h5py.File("0.hdf5") as f:
    rgb, depth, instances = f["colors"][()], f["depth"][()], f["instance_segmaps"][()]
    raw = f["instance_attribute_maps"][()]
    attributes = json.loads(raw.decode() if isinstance(raw, bytes) else str(raw))
```

### `render.json`

| Поле | Что |
|---|---|
| `camera_locations` | четыре положения камеры в мире комнаты (нормированные единицы) |
| `camera_clearances`, `requested_min_clearance`, `relaxed_camera_count` | зазоры от камер до поверхностей |
| `camera_height_fraction`, `camera_clip_planes`, `camera_rotation_euler_xyz` | параметры камеры |
| `cameras_on_furniture_fallback` | пришлось ли ставить камеры над мебелью |
| `layout`, `bounds_min`, `bounds_max` | восстановленный контур пола, высоты пола и потолка |
| `light_locations`, `samples`, `resolution`, `views` | свет и параметры рендера |
| `coordinate_frame`, `gltf_to_blender_axes` | мир Blender, Z вверх; оси `["x", "-z", "y"]` |
| `metric_scale_certified` | всегда `false`: единицы рендера не метры |
| `plan_only` | был ли это только план камер |
| `implementation_sha256` | хеши `render.py`, `camera_policy.py`, `room_layout.py`, `glb_geometry.py` |

Разметка берёт камеры и контур отсюда, а не пересчитывает их.

## Эталонная разметка

### `rgb/<часть>/<дом>/<комната>/<вид>.png` и `manifests/<часть>.jsonl`

Цвет каждого вида и перечень видов:
`{"sample_id", "input": <путь PNG>, "metadata": {split, house_id, room_id, view_index, hdf5, projection, dataset}}`.

### `ground_truth/<часть>/<дом>/<комната>/<вид>.json`

```json
{
  "layout": {"min_corner": [...], "max_corner": [...]},
  "objects": [{
    "object_id": "Chair_<uuid>_1", "label": "chair", "score": 1.0,
    "bbox": {"center": [...], "size": [...], "basis": [[...], [...], [0, 0, 1]]},
    "attributes": {"source_glb": "<дом>/<комната>/Chair_<uuid>_1.glb",
                   "fine_class": "chair/dining chair",
                   "shape": "EXP/objects/chair/<дом>__<комната>__Chair_<uuid>_1/mesh.ply"}
  }],
  "relations": [{"source_id": "...", "target_id": "...", "relation_type": "touching", "score": 1.0}],
  "metadata": {
    "coordinate_frame": "camera_centered_xyz_z_up",
    "camera_location_world": [...], "metric_scale": 2.87, "metric_scale_source": "table",
    "layout_geometry_world": {"polygon": {...}, "floor_z": ..., "ceiling_z": ...},
    "walls": [...], "relation_expand_distance": 0.1
  }
}
```

- `objects[].bbox` и `layout` — в системе камеры, в метрах.
- `layout` — охватывающая рамка контура по осям. Точная форма комнаты — многоугольник
  `metadata.layout_geometry_world` (GeoJSON, мир, метры) с высотами пола и потолка.
  Целевой макет — вертикальное вытягивание контура пола между этими высотами:
  непрямоугольные комнаты описываются точно, многоуровневые потолки — нет.
- Контур очищен от вершин, которые не являются углами (точки на прямой стене, обрезки
  у наличников); площадь при этом меняется не больше чем на 3 %.
- `label` — обучающий класс, `attributes.fine_class` — подробный класс исходного 3D-FRONT.
  Предмет, класса которого нет в списке, получает `other`.
- `attributes.shape` появляется после этапа `shape`, `relations` — после этапа `relations`.

Отношения:

| `relation_type` | Между чем |
|---|---|
| `touching` | предмет и предмет |
| `touching_floor` | предмет и `layout::floor` |
| `touching_ceiling` | предмет и `layout::ceiling` |
| `touching_wall` | предмет и `layout::wall_<i>` |

Касание: рамки, расширенные на `relation_expand_distance` (0.1 м), пересекаются и по
высоте, и по следу. Стена — тонкая рамка (5 см) на каждом ребре очищенного контура,
их список лежит в `metadata.walls`.

`manifests_gt/<часть>.jsonl` — то же, что `manifests/`, плюс поле `ground_truth`.

### `objects/<класс>/<дом>__<комната>__<имя GLB>/mesh.ply`

Сетка предмета в единичной рамке экземпляра: `(p − center) · basisᵀ / size`. Обратно:
умножить на `size`, повернуть на `basis`, прибавить `center`. Сетка не замкнута.

### Служебные файлы `state/`

| Файл | Что |
|---|---|
| `classes.json` | список обучающих классов; его читают все экспортёры и обучение |
| `metric_scale.json` | масштаб каждой комнаты и его источник |
| `ground_truth.json`, `relations.json`, `shape.json`, `coco.json` | отчёты этапов |
| `finalize.json` | готовы ли все комнаты к разметке |

## COCO

### `coco/<часть>.json` — двумерная детекция

Стандартный COCO с двумя особенностями.

- **Шов панорамы.** Предмет на шве распадается на две части у левого и правого края.
  Если в кадре, сдвинутом на половину ширины, он цел, аннотация пишется в этом кадре.
  Сдвинутый кадр лежит рядом как `<вид>.frame1.png`, у изображения поле
  `panorama_frame: 1`. Предмет, разрезанный в обоих кадрах (охватывает почти весь
  горизонт), делится на две части с плотными рамками.
- **Маски** — несжатый RLE (`{"size": [H, W], "counts": [...]}`, по столбцам, как в
  pycocotools).

`file_name` указан относительно `EXP`. Категории: `id` — номер в `state/classes.json`
плюс один.
